# 계획1 최종 파이프라인 재시험 진실명세서

## 목적
기존 42개 후보 조건을 다시 평가해 OCR·역할·번역 조합 네 가지를 실제 앱 경로에서 비교한다. 그중 선택한 구성을 최종 64개 원본 × 8조건(512회 실행)로 검증하고, 검증된 변경을 `develop`을 거쳐 `main`에 반영한 뒤 릴리스한다.

## 단계
| 단계 | 내용 | 종료 근거 |
|---|---|---|
| N1 | 기존 42조건 재평가 | 완료 |
| N2 | 공통 결함 2건 수리, 실행기 검사 | 완료 (양 Windows 환경 full36/component35 통과) |
| N3 | 자원·소유권 확인, 실패 표본 진단 | 진단 수행. 원래 역할 timeout은 미판정 |
| N4 | 역할·번역 구조(F0/F1/F2)와 번역 후보 | 작은 gate 수행. OFF/F2 확대 보류 |
| N5 | OCR·검출 후보 선별 | 작은 gate 수행. 최종 구성 선택은 미완료 |
| N6 | 네 구성(P00/P10/P01/P11) × 공통 6페이지 | 기존 기록 18/24. 계수·사후 감사 재확인 중, P11 0/6 |
| N7 | 원본·출력 대응 판정, 원인 수리, D1 선택·속도 검증 | 대기 |
| N8 | 최종 512회 실행, 전체 검사 | 이번 최종 pin의 실행 미시작 |
| N9 | D2 자료 제출 | 대기 |
| N10–N12 | 기능별 커밋 → `develop` PR → `main` 승격·태그·Release | 대기 |

## 불변 조건
- 원본 이미지·입력 manifest·block ID·geometry는 바꾸지 않는다. 원본으로 대체한 결과는 성공으로 세지 않는다.
- 실제 모델 job은 한 번에 하나만 돌리고, 끝날 때마다 GPU 반환을 확인한 뒤 다음 job으로 넘어간다.
- timeout 증가, 숨은 retry/skip, provider 대체로 테스트를 통과시키지 않는다.
- 측정하지 않은 값은 0이나 만점으로 채우지 않고 null로 둔다. 단계 시간의 합을 연속 실행 시간이라고 부르지 않는다.
- 외부 GPU 점유 process는 차단 조건이 아니다. 종료하지 않고 관측값으로만 기록한다.
- 신규 Photoshop/PSD 개선은 범위에서 뺀다. 기존 지원은 유지한다. InternVL/Magi와 quant/KV/Spotting 계열은 진입 조건이 충족될 때만 시험한다.

## 현재 판정 기준과 추적
- 2026-11-13 상태 확인: 기존 완료 집계와 진단 전용 표지의 자격 관계가 아직 정리되지 않았다. 기록상 완료와 독립 재검증 완료를 구분한다.
- 원본의 필수 내용·보존 대상·효과음과 실제 출력의 대응을 판정한다. 처리 블록 수는 진단값이며 같게 맞추는 것을 품질 기준으로 삼지 않는다.
- 품질 오류의 원인을 먼저 수리하고 품질·속도·메모리에서 서로 우열이 갈리는 후보를 비교한다. 미판정 결과는 자동 우승으로 선택하지 않는다.
- 검증·보고가 완료된 기능 PR은 develop으로 통합한다. main 승격·태그·Release는 최종 결과 검수 뒤 진행한다.
