# Gemma 최종 A/B blind 품질 검수 workflow

## 목적

protocol v4는 이미 저장된 protocol v3 번역 결과 중 clean한 baseline 2회와
grouped F16 2회만 가져와 사용자 품질 검수표를 만든다. 새 모델 요청,
Docker 시작, 번역 재실행은 하지 않는다.

Q8은 탈락 증거만 재검증하며 A/B 후보에는 포함하지 않는다.

## 순서

1. source suite의 protocol, 결과 파일 SHA-256, 입력, OCR snapshot, 모델,
   runtime, 번역 동작 계약을 다시 검증한다.
2. baseline과 grouped F16의 1·2라운드 결과가 모두 clean한지 확인한다.
3. 네 결과의 292개 row ID, 페이지, 블록, 원문 SHA-256과 순서를 대조한다.
4. A/B 매핑을 한 번 무작위로 정하고 두 라운드에 동일하게 적용한다.
5. 설정명, 속도, blind key를 제외한 HTML·CSV 검수표를 Git 밖에 쓴다.
6. 사용자는 292행의 A1·A2·B1·B2를 모두 검수한다.
7. validator가 immutable 열, 행 수, 순서, 판정값, 회귀 유형과 메모를
   검사한다.
8. 292행이 모두 유효한 경우에만 명시적 확인문과 함께 unblind한다.
9. grouped 후보에서 명시적 의미 회귀가 하나라도 나오면 승격을 중단한다.

## 품질 판정 기준

자연스러운 표현 차이는 허용한다. 아래 의미가 달라질 때만 회귀다.

- 화자
- 관계
- 부정
- 행동
- 대상
- 숫자
- 고유명사
- 명시적 의미

회귀를 표시한 행에는 회귀 유형과 근거 메모가 반드시 있어야 한다.

## 종료점

protocol v4의 종료점은 사용자 blind 품질 승인 또는 품질 탈락이다.
승인 전에는 제품 기본값 변경과 전체 파이프라인 비교를 시작하지 않는다.
품질 승인은 다음 제품 브랜치 구현을 여는 gate일 뿐이며 최종 제품 승격
승인이 아니다.
