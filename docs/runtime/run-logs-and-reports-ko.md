# 실행 로그와 리포트

앱이 어디에 무엇을 기록하는지, 그리고 배치가 끝난 뒤 무엇을 확인할 수 있는지
정리합니다.

## 어디에 남는가

모두 **저장소 안의 `logs/`** 아래입니다. 로그를 소스·산출물과 같은 곳에 두면
문제가 생겼을 때 바로 찾을 수 있습니다. 이 폴더는 `.gitignore` 대상이라 저장소를
오염시키지 않습니다.

```
<저장소>/logs/
├─ comic-translate.log        앱 전역 로그 (8 MiB마다 회전, 5개 보관)
├─ memlog_*.jsonl             메모리 진단 로그
└─ runs/                      실행 리포트
```

다른 곳에 두려면 `COMIC_TRANSLATE_LOG_DIR` 로 지정합니다. 저장소 폴더에 쓸 수
없는 설치형 환경에서는 사용자 데이터 폴더로 자동으로 물러납니다 — 로그를 못 써서
앱이 멈추는 일은 없습니다.

실행 리포트는 배치가 끝날 때마다 두 개가 한 쌍으로 생깁니다. 파일명의 타임스탬프는
`모두 번역` 을 누른 시각입니다.

| 경로 | 내용 |
| --- | --- |
| `runs/run_<시작시각>.txt` | 사람이 읽는 실행 요약 |
| `runs/run_<시작시각>.json` | 같은 내용의 기계 판독용 |

예전에는 로깅이 stderr 로만 나갔습니다. 콘솔 없이 실행하는 일반 경로에서는 그대로
사라져서, 배치 도중 터진 traceback 을 사후에 확인할 방법이 없었습니다. 이제
처리되지 않은 예외는 메인 스레드와 워커 스레드 모두 파일에 남습니다.

## 실행 리포트에 담기는 것

전부 **실측값**입니다. 추정하거나 단계 합으로 역산하지 않습니다.

- **전체 소요**: 사용자가 `모두 번역`을 누른 순간부터 끝날 때까지. 컨테이너 기동과
  모델 적재도 사용자가 기다린 시간이므로 포함합니다.
- **단계별 소요**: 감지 / OCR / 번역 / 인페인팅 / 렌더 각각의 초·분과 전체 대비 비중.
  긴 순서로 정렬됩니다.
- **입력 대비 출력 수**와 페이지당 초.
- **폴백 저장 목록**: 어떤 페이지가 어떤 이미지로, 어느 단계의 무슨 이유 때문에
  저장됐는지.
- **저장 실패 목록**: 그래도 파일을 만들지 못한 페이지.

```
============================================================
자동 번역 실행 리포트
============================================================
시작: 2026-08-07 03:18:25
전체 소요: 00:26:48 (26.8분)
페이지: 366장
페이지당: 4.39초

출력: 366장 / 입력 366장
폴백 저장: 1장
  - 233.png [source] OCR: Direct Paddle llama.cpp OCR response was truncated.

단계별 실측 소요 (긴 순서)
------------------------------------------------------------
  번역            00:15:00     15.0분  56.0%
  인페인팅          00:07:47      7.8분  29.0%
  렌더            00:01:50      1.8분   6.8%
  OCR           00:01:11      1.2분   4.4%
  말풍선 감지        00:01:00      1.0분   3.7%
============================================================
```

## 출력 개수는 항상 입력과 같아야 한다

한 단계가 실패해도 페이지가 출력에서 사라지지 않습니다. 렌더까지 가지 못한
페이지는 남아 있는 최선의 이미지로 저장합니다.

1. 정상 렌더 결과
2. 인페인팅만 된 이미지 (번역이 실패했을 때)
3. 원본 이미지 (감지나 OCR 이 실패했을 때)

폴백은 정상 렌더와 **같은 내보내기 경로**를 씁니다. 아카이브 모드의 페이지 번호와
파일명 규칙이 어긋나면 안 되기 때문입니다.

품질이 떨어지는 것과 결과가 없는 것은 다릅니다. 그래서 모든 폴백은 리포트와 처리
요약에 남습니다. 조용한 폴백은 조용한 누락만큼 나쁩니다. 그래도 저장하지 못한
페이지가 있으면 배치 리포트에 입력·출력 개수와 파일명을 올립니다.

## 속도를 비교할 때

`runs\` 의 JSON 두 개를 비교하면 됩니다. 같은 작품·같은 설정에서 `total_wall_sec`
와 `stages[].seconds` 를 보면 어느 단계가 좋아졌는지 바로 드러납니다.

이 기록은 리포트가 도입된 이후 실행부터 쌓입니다. 그 이전 실행은 아무 기록도
남기지 않았으므로 비교 대상이 없습니다.
